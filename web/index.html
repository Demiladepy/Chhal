// closed-loop adversarial fraud engine //

The fraud loop that fights back.

Chhal (छल — “deception”) is one self-enclosing loop for GenAI payment fraud. A red-team agent invents attacks; a constrained optimizer sharpens them until they slip past the model; the defense retrains on what got through. Every deception it invents becomes the training ground for a defense that learns to see through it — and the arms race is the demo.

// the one idea //

Most teams submit three things. We submit the loop between them.

The brief says it twice: the best solutions turn their own simulated attacks into the training ground for a stronger defense. So Chhal isn’t an attack deck, a data generator and a classifier sitting apart — it’s one loop where each half makes the other stronger, and the loop itself is what we put on screen.

The rule that keeps it honest: an attack may only emit columns the detector already sees for real traffic. No invented feature — otherwise “detection” is trivial and the result is fake.

// how one pass runs //

A single iteration, end to end.

01 — IDENTIFY

Invent

A taxonomy of where GenAI actually changes payment fraud. Five vectors are built as live code; the rest catalogued for breadth.

02 — GENERATE

Render

Attacks are emitted as transactions in the frozen feature space, mounted on real never-fraudulent accounts whose issuer-side context they inherit — so they are plausible by construction, not by assertion.

03 — EVADE

Sharpen

The constrained optimizer nudges attacker-controlled features to slip past the current model — without leaving the executable manifold.

04 — DEFEND

Retrain

The detector learns the training split; a held-out novel split it never saw measures whether it generalizes — then the loop turns again.

// similarity isn’t security //

A static model isn’t a defense — it’s a fixed target.

Trained once on yesterday’s fraud, a classifier is a puzzle an LLM can solve offline. Chhal makes the target move.

Static detector

  • ✕ Catches almost none of the adaptive attacks — they’re tuned to look normal.
  • ✕ Every gap it leaves is stable, so an attacker finds it once and reuses it.
  • ✕ “Realistic” attacks are asserted, never measured against the real distribution.
  • ✕ Improvement on training data can be pure memorisation — no proof it generalizes.

Chhal, closed loop

  • ✓ Benchmark recall climbs from 0% to 84.9% on attacks the model never trained on, at a 0.1% false-positive budget — a budget the run verifies it honoured (0.0996% realised).
  • ✓ Each gap the red team finds becomes the next training signal — the target moves.
  • ✓ Fidelity is a number: on-manifold rate and per-vector KS versus real traffic.
  • ✓ A frozen held-out split proves generalisation, not memorisation. No leakage.

// the money chart //

Two honest lines, kept separate.

Blue generalisation — the money line.

A fixed benchmark of hard adaptive attacks, built once and never trained on. A static model catches almost none of it. One loop pass and the retrained detector holds it near the top — generalisation, not memorisation.

Red pressure — the honest gap.

Each iteration the red team optimises a fresh batch against the current model and holds it out. It stays volatile: the attacker keeps finding evasions the just-retrained model partly misses. The gap is the arms race, unfinished.

“Isn’t this circular — you attack your own model, retrain, and of course it improves?”

// fixed benchmarkHard attacks built once against the baseline and never trained on. Improving on them is generalisation to unseen fraud.
// split, not shuffledEach batch is split by attack into a train portion and a held-out novel portion — the model learns one, is judged on the other.
// no leakageThe base train/test split is frozen before any attack is injected. Benchmark and pressure attacks touch neither.
// the gap is the pointBlue holds the known shape; red keeps probing new ones. We show an arms race, not a solved problem.
